# Car Service Requisition System

Role-based company transport requisition workflow built with Next.js 16, TypeScript, Tailwind CSS, and Supabase.

## Included scope

- Request submission, approval/rejection, and vehicle/driver assignment
- Daily vehicle/driver sourcing by GA without fixed fleet master records
- Driver acceptance, departure, mileage, completion, and expenses
- Weekly schedule, resource management, and Excel/PDF reports
- Supabase email/password authentication and PostgreSQL Row-Level Security
- Tiger Space OT transport requests (Tiger Space remains the OT source of truth)
- Browser-only demo fallback when Supabase environment variables are absent

## Local development

Requirements: Node.js 18.17 or newer and npm.

```bash
npm install
npm run dev
```

Open `http://localhost:3000`. With no Supabase variables, the role switcher and seeded browser data are used. Demo state is stored under `csrs-mvp-data` in local storage.

## Supabase production setup

1. Create a Supabase project.
2. Run `supabase/migrations/202607140001_initial.sql` in the Supabase SQL Editor, or apply it through the Supabase CLI.
3. Copy `.env.example` to `.env.local` and set:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

4. Create users in Supabase Authentication. A trigger creates each profile as an inactive-department requester; authorization roles are never accepted from user-editable metadata.
5. Create company departments and assign each profile from the SQL Editor. Promote roles only through trusted administration:

```sql
insert into public.departments (name, code)
values ('Engineering', 'ENG')
on conflict (code) do update set name = excluded.name;

update public.profiles
set
  employee_id = 'GA001',
  full_name = 'Kanya Boonmee',
  department_id = (select id from public.departments where code = 'ENG'),
  role = 'admin'
where email = 'kanya@company.example';
```

The production role is read from `public.profiles`; the demo role switcher is disabled. Middleware requires a valid Supabase session, the shell blocks cross-role routes, and RLS/database functions enforce authorization even if the browser is bypassed.

## Architecture

- `app/`: Next.js App Router pages organized by role
- `components/app-provider.tsx`: auth, data state, demo fallback, and repository boundary
- `lib/supabase/`: browser/server clients, session refresh, and data repository
- `supabase/migrations/`: schema, indexes, RLS, and atomic workflow functions
- `lib/types.ts`: application domain types
- `lib/validation.ts`: Zod request/assignment/trip validation
- `lib/business.ts`: display, overlap preview, and cost utilities
- `lib/mock-data.ts`: local demo records

Production booking numbers are generated by PostgreSQL. Outside-company requests use department approval; OT requests record only employees who need transportation and move directly to GA planning after Tiger Space confirmation. GA enters the actual daily vehicles and drivers, and assignment is committed through a role-checked database function.

See `docs/transport-workflow-phases.md` for the phased implementation and remaining operational hardening work.
